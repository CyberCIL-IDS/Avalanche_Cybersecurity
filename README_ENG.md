# 🇬🇧 English Avalanche Cybersecurity - IDS Continual Learning

This project implements an **Intrusion Detection System (IDS)** based on **Continual Learning** techniques using the [Avalanche](https://avalanche.continualai.org/)library. The system is designed to adapt to new types of attacks over time without forgetting previously learned knowledge (prevention of *Catastrophic Forgetting*).

## 🚀 Key Features

* **Supported Datasets**:
    * **UNSW-NB15**: Network intrusion detection dataset.
    * **CICIDS-2017**: Comprehensive dataset for modern attacks (DDoS, Brute Force, etc.).
* **Continual Learning Strategies:**:
    * **DER** (Dark Experience Replay)
    * **MER** (Meta-Experience Replay)
    * **ICaRL** (Incremental Classifier and Representation Learning)
* **Benchmark Modes**:
    * **Fixed**: Learning on fixed tasks.
    * **Incremental**: Incremental learning (Class-Incremental or Domain-Incremental).
    * **Half**: Split learning (half of the classes in the first step, half in the second).
* **Automatic Optimization**: Integration with **Optuna** for optimal hyperparameter search.
* **Advanced Preprocessing**: Automated pipelines for data cleaning, feature engineering, and class balancing.

## ⚙️ Detailed Configuration

All execution logic is centralized in the `config.yaml` file. Below explains how to configure the critical sections to achieve the best results.

### 1. `benchmark` Section

This section defines how the main training (`main.py`) will be executed and which Continual Learning scenario to simulate.

* `strategy`: The continual learning strategy to use.
    * Options: `DER`, `MER`, `ICaRL`.
* `mode`: The method for splitting the dataset and tasks.
    * `fixed`: Standard training on a fixed set of data.
    * `incremental`: Data is provided in multiple sequential steps (experiences).
    * `half`: The dataset is split into two equal parts (half the classes in the first step, the other half in the second).
* `param`: Numeric parameter linked to the chosen mode.
    * In `fixed` mode: set to `1`.
    * In `incremental` mode: Represents the number of experiences (steps) to divide the training into.
    * In `half` mode: This value is ignored.
* `best_params_path`: Absolute or relative path to the JSON file containing optimized hyperparameters (generated by Optuna). Example: `"utils/optuna/optuna_best_params2.json"`.

### 2. `optuna` Section

This section controls the optimization script (`optimization.py`). It is crucial to understand the `all` parameter to decide what to iterate over.

* `n_trials`: Number of optimization attempts per configuration (e.g., 20 for quick tests, 100+ for robust results).
* `pruner`: Algorithm to stop unpromising trials (e.g., `"HyperbandPruner"` or `"MedianPruner"`).
* `all` **(IMPORTANT)**: Determines the scope of the search.
    * `true`: Optuna **ignores** the single settings in the `benchmark` section and runs a nested loop over ALL lists defined under `optuna`.
        * Example: If `modes: ["fixed", "incremental"]` and `strategies: ["DER", "MER"]`, Optuna will search for best params for: `(fixed+DER)`, `(fixed+MER)`, `(incremental+DER)`, etc.
    * `false`: Optuna will optimize **only** the specific configuration (`mode/strategy/param`) currently active in the `benchmark` section.
* **Iteration lists (used only if `all: true`):**:
    * `modes`: List of modes to test (e.g. `["half", "incremental"]`).
    * `strategies`: List of strategies (e.g. `["ICaRL", "MER"]`).
    * `params`: List of numeric parameters (e.g. `[1, 2, 5]`).

### 3. Example `config.yaml` Workflow
If you want to optimize and then train an **ICaRL** model in **Incremental** mode with **5 steps**:

1. Set `optuna.all: false`.
2. Set `benchmark.strategy: "ICaRL"`.
3. Set `benchmark.mode: "incremental"`.
4. Set `benchmark.param: 5`.
5. Run `python optimization.py`.
6. Update `benchmark.best_params_path` with the newly created JSON file.
7. Run `python main.py`.

## ▶️ Usage

The typical workflow involves three phases: Optimization, Training, and Prediction.

### 1. Hyperparameter Optimization (Optional)
Before training the final model, it is advisable to search for the best hyperparameters (learning rate, batch size, etc.).

```bash
python optimization.py [output_path.json]
```

### 2. Training and Benchmark
Execute training using the configuration specified in `config.yaml`. The script will automatically load the best parameters found in the JSON pointed to by `best_params_path`.

```bash
python main.py
```

* The trained model will be saved in the`checkpoints/` folder.
* Metric plots (accuracy, forgetting) will be saved in `utils/plot_NOMEDATASET/`.

### 3. Prediction (Inference)
To perform predictions on a test dataset and generate the confusion matrix:

```bash
python predict.py
```

* Ensure that `strategy`, `mode` and `param` are set correctly in `config.yaml` corresponding to the checkpoint you want to load.
* Results will be saved in `datasets/predictions.csv`.

## 📊 Output and Results

* **Models**: Saved as `model_checkpoint_{strategy}_{mode}_{param}.pth`.
* **Preprocessing**: The `preprocessor` and `label_encoder` objects are saved as `.pkl` to ensure consistency between training and inference.
* **Plots**: Confusion matrices and accuracy trend plots during incremental phases are generated.
